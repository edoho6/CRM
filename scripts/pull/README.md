# משיכת מידע מחשבונות שלך

שלושה כלים שמושכים מידע מחשבונות שיש לך באתרים אחרים — Meta (פייסבוק, אינסטגרם, WhatsApp
Business), או כל אתר שיש לך בו שם משתמש וסיסמה — אל המחשב הזה, כקבצים שאפשר לקרוא ולעבד.

## מה לא קורה כאן, ולמה

**אף סיסמה לא נכתבת בצ'אט, בשורת הפקודה או בקובץ.** לא בגלל שאי אפשר — בגלל שזה
נגמר רע בשלוש דרכים: הצ'אט והטרמינל נשמרים בקבצי היסטוריה על הדיסק; אתר גדול (Meta,
גוגל, בנקים) מזהה כניסה של סקריפט ונועל את החשבון; ואצל Meta זה גם הפרה של תנאי
השימוש. לכן:

| סוג האתר                                     | הדרך                                                                                    | הכלי                                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| יש לו API רשמי (Meta, גוגל, רוב שירותי הענן) | מפתח גישה (token) שמייצרים באתר שלהם ומדביקים בטרמינל                                   | `meta.mjs` (ל-Meta), ולאתר אחר — אותו דפוס, סקריפט חדש                                                                    |
| יש לו "ייצוא" רשמי                           | קובץ שמורידים ביד, ואני קורא אותו                                                       | פייסבוק: הגדרות ← המידע שלך ← "הורדת המידע שלך" (JSON). WhatsApp: פתיחת צ׳אט ← ⋮ ← "ייצוא צ׳אט". גוגל: takeout.google.com |
| אין API ואין ייצוא                           | מתחברים **ביד** בחלון דפדפן שהסקריפט פותח; הוא זוכר את ההתחברות, ומאותו רגע מושך עמודים | `login.mjs` ואז `site.mjs`                                                                                                |

מה שנמשך נכתב ל-`test-results/pull/` — תיקייה שלא נכנסת ל-git. זה מידע אישי שלך ושל
אנשים שכתבו לך; הוא נשאר במחשב הזה, ומוחקים אותו כשסיימו איתו.

## Meta — צעד אחר צעד

ה-API של Meta עובד עם "מפתח גישה" (access token) שמייצרים באתר המפתחים שלהם, בחשבון
שלך, לאפליקציה שלך. באפליקציה במצב פיתוח כל ההרשאות עובדות **למי שיש לו תפקיד
באפליקציה** — כלומר לך — בלי אישור של Meta. פעם אחת:

1. נכנסים ל-[developers.facebook.com](https://developers.facebook.com) עם חשבון הפייסבוק שלך.
2. למעלה מימין **My Apps** ← **Create App**. סוג: **Business** (או Other ← Business).
   שם: כל שם, למשל "Herbalist pull". חשבון עסקי: אם יש — בוחרים אותו. **Create App**.

ובכל פעם שמושכים (המפתח חי כשעה):

3. **Tools** (למעלה) ← **Graph API Explorer**.
4. מימין: **Meta App** = האפליקציה שיצרת. **User or Page** = User Token.
5. **Permissions** ← מוסיפים לפי מה שרוצים למשוך (הרשימה למטה) ← **Generate Access Token**
   ← חלון של פייסבוק מבקש אישור ← מאשרים.
6. מעתיקים את הטקסט הארוך משדה **Access Token**.
7. בטרמינל:
   ```
   node scripts/pull/meta.mjs
   ```
   הסקריפט שואל `Meta access token (not shown):` — מדביקים (קליק ימני בטרמינל) ו-Enter.
   כלום לא מוצג בזמן ההדבקה; זה בכוונה.

| חלק         | מה יוצא                                                                                  | הרשאות ב-Explorer                                                                        |
| ----------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `me`        | מי אני (בדיקה שהמפתח עובד)                                                               | —                                                                                        |
| `pages`     | הדפים העסקיים שלך: פרטים, פוסטים עם לייקים/תגובות/שיתופים, דירוגים, ותיבת ההודעות של הדף | `pages_show_list`, `pages_read_engagement`, `pages_read_user_content`, `pages_messaging` |
| `instagram` | חשבון אינסטגרם עסקי שמחובר לדף: פרופיל, עוקבים, כל הפוסטים                               | `pages_show_list`, `instagram_basic`                                                     |
| `leads`     | טופסי לידים של הדפים וכל הליד שנשלח בהם (מודעות "השאירו פרטים")                          | `pages_show_list`, `pages_manage_ads`, `leads_retrieval`                                 |
| `whatsapp`  | חשבון ה-WhatsApp Business: המספרים, דירוג האיכות, התבניות המאושרות                       | `business_management`, `whatsapp_business_management`                                    |
| `ads`       | חשבונות המודעות: קמפיינים ונתוני 90 יום (הוצאה, חשיפות, קליקים)                          | `ads_read`                                                                               |

`--what=pages,leads` מושך רק חלק; בלי `--what` — הכול, וחלק שההרשאה שלו חסרה מדווח על
זה וממשיך. `--path=/me/accounts --fields=id,name` מושך כל כתובת אחרת ב-Graph API.

**מה לא יוצא מ-Meta, בשום מפתח:** שיחות ה-WhatsApp עצמן. ה-API רואה הודעה רק ברגע
שהיא מגיעה ל-webhook (וזה מה שהמערכת כבר עושה דרך Make). ההיסטוריה של הצ׳אטים יוצאת
רק מהאפליקציה בטלפון ("ייצוא צ׳אט"), וגם הפרופיל האישי שלך (לא הדפים) יוצא רק דרך
"הורדת המידע שלך". את שני הקבצים האלה אני יודע לקרוא — לשלוח לי, ואבנה קורא.

## כל אתר אחר

```
node scripts/pull/login.mjs --site=my-bank --url=https://www.example.com/login
```

נפתח חלון Edge אמיתי, נפרד מהדפדפן הרגיל, עם פרופיל משלו בתיקייה `.auth/my-bank/`.
מתחברים בו **ביד** כרגיל — סיסמה, קוד לטלפון, "לזכור מכשיר זה". כשבפנים, חוזרים
לטרמינל ולוחצים Enter. החלון נסגר, וההתחברות נשארת בפרופיל (לא ב-git). מכאן:

```
node scripts/pull/site.mjs --site=my-bank --url=https://www.example.com/account/history
```

פותח את העמוד מחובר, בלי חלון, ושומר ב-`test-results/pull/my-bank/<תאריך-שעה>/`:

- `page.txt` — הטקסט של העמוד כפי שקוראים אותו; `page.html` — העמוד כולו; `page.png` — צילום
- `links.json` — כל הקישורים בעמוד, כדי למצוא את העמוד הבא שכדאי למשוך
- `json/` — **כל תשובת JSON שהעמוד קיבל בזמן הטעינה.** ברוב האתרים המודרניים זה המידע
  עצמו, מסודר, לפני שהעמוד צייר אותו — לרוב שווה יותר מהטקסט
- `index.json` — מה נפתח, מתי, ואיזה קובץ ב-`json/` הגיע מאיזו כתובת

`--scroll=5` גולל למטה חמש פעמים לרשימה שנטענת תוך כדי גלילה; `--wait-for="table"` מחכה
שטבלה תופיע; `--show` מציג את החלון כדי לראות מה קורה. אם העמוד שנפתח הוא דף כניסה —
ההתחברות פגה, ומריצים `login.mjs` שוב. יציאה מהאתר = מחיקת `.auth/<site>/` ושל `.auth/<site>.cookies.json` שלצידה (העוגיות
נשמרות גם שם, כי כניסה בלי "זכור אותי" נמחקת מהפרופיל כשהחלון נסגר).

**אתרים שמסרבים להתחבר בחלון הזה** (גוגל מציג "הדפדפן לא מאובטח", בנקים לפעמים): להם
נשארות שתי הדרכים הראשונות בטבלה — API עם מפתח, או ייצוא.

## ברא צמחים — שלושת האינדקסים

`bara.mjs` הוא הקורא הספציפי הראשון: אחרי `login.mjs --site=bara --url=https://barapro.co.il/`
(הכפתור "כניסה" באתר הוא "שלום" עם אייקון האדם, למעלה משמאל) הוא עובר על אינדקס הפורמולות
הקלאסיות, אינדקס צמחי המרפא (בשלושת מצבי השם — פינין, בוטני, עברי — כי הרשימות שונות: צמחי
מערב ותמציות מופיעים רק תחת השם הבוטני) ואינדקס בדיקות המעבדה. האתר מציג כל אינדקס אות-אות,
ולכן הוא קורא כל אות של כל מצב, ואז כל ערך.

```
node scripts/pull/bara.mjs --limit=3     # ניסיון: שלושה ערכים מכל אינדקס
node scripts/pull/bara.mjs               # הכול (כ-20–30 דקות, עמוד בשנייה)
node scripts/pull/bara.mjs --index=herbs # אינדקס אחד
```

הפלט ב-`test-results/pull/bara/index/<אינדקס>/`: `entries.json` (רשומה לכל ערך — לפורמולה:
שם, רכיבים עם מינון וקישור לצמח, "אודות", "יתרונות", "הערות", ומוצר המדף; לצמח: כל הטקסט של
המונוגרף, השדות "תווית: ערך" שזוהו בו, התמונה וקובץ ההגייה; לבדיקה: הטקסט והשדות ערכים
תקינים / גבוהים / נמוכים), `pages/` (העמודים כפי שהוגשו) ו-`report.txt`. ריצה שנקטעה ממשיכה
מאיפה שעצרה; `--fresh` מושך הכול מחדש.

## ומה הלאה

`site.mjs` הוא כלי כללי; הקורא **הספציפי** — שהופך את ה-JSON של אתר מסוים לטבלה, או
מכניס לידים מפייסבוק כמטופלים פוטנציאליים במערכת — נבנה לפי האתר. כדי שאבנה אותו
צריך שלושה דברים: איזה אתר, איזה עמוד (או איזה חלק ב-Meta), ומה רוצים לעשות עם המידע.
