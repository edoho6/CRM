# הספרייה המקצועית — הצנרת

הספרייה עונה למטפלים על שאלות מקצועיות **רק מתוך מקורות שהוזנו לה**: קבצי PDF ו-Word מתיקייה ב-Google
Drive (ובעתיד עמודים מאתרים ברשימה). הסקריפטים כאן קוראים את הקבצים, חותכים אותם לקטעים, מחשבים לכל קטע
embedding ב-Voyage AI, ומעלים למסד (`library_sources`, `library_chunks`). המענה עצמו הוא באפליקציה
(`apps/web/features/library/`), דרך `/api/library/ask`.

## מה צריך לפני הריצה הראשונה

| מה | איפה | למה |
|---|---|---|
| `vector` מופעל ב-Supabase | Dashboard → Database → Extensions | החיפוש הסמנטי (pgvector) |
| `37_library_to_run.sql` הורץ | SQL editor | הטבלאות והפונקציות |
| `VOYAGE_API_KEY` | `apps/web/.env.local` (וב-Vercel) | ה-embeddings, בסקריפט ובמענה |
| `ANTHROPIC_API_KEY` | `apps/web/.env.local` (וב-Vercel) | המענה |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | `apps/web/.env.local` — נתיב לקובץ JSON **מחוץ לריפו** | הקריאה מ-Drive |
| `LIBRARY_DRIVE_FOLDER_ID` | `apps/web/.env.local` | המזהה מכתובת התיקייה בדרייב |

הצעדים בגוגל (חשבון שירות, שיתוף התיקייה) כתובים אחד-אחד ב-`DEPLOY.md`, בסעיף "ספרייה מקצועית".

## הפקודות

```
node scripts/library/ingest.mjs                       # קורא את תיקיית הדרייב, חותך, מחשב embeddings, מעלה
node scripts/library/ingest.mjs --dry                 # רק קורא וחותך — כמה קטעים יצאו, בלי להעלות
node scripts/library/ingest.mjs --limit=10            # עשרת הקבצים הראשונים (לניסיון)
node scripts/library/ingest.mjs --refresh             # גם קבצים שלא השתנו
node scripts/library/ingest.mjs --folder "C:\path"    # תיקייה במחשב במקום הדרייב
```

ההעלאה שואלת אימייל וסיסמה של אדמין הפלטפורמה בטרמינל (הסיסמה מוסתרת), כמו הייבוא הרפואי. קובץ שלא
השתנה (אותו hash) נדלג; קובץ שנעלם מהתיקייה מוסר מהספרייה כשנקראה כל התיקייה. המטמון ב-`.cache/library/`
(hashים ו-embeddings), ולכן ריצה חוזרת עולה רק על מה שחדש.

מה נקרא: PDF (עם שכבת טקסט; סריקה בלי טקסט מדווחת ונדלגת), Word (DOCX), Google Docs (מיוצאים כ-Word), TXT,
Markdown. גיליונות ומצגות לא.

## אתרים

```
node scripts/library/crawl.mjs                        # קורא את האתרים ב-scripts/library/sites.json
node scripts/library/crawl.mjs --dry --limit=20       # ניסיון על עשרים עמודים, בלי להעלות
```

`sites.json` הוא רשימה של רשומות כאלה:

```json
[
  { "url": "https://example.org/formulas/", "maxPages": 200, "include": "/formulas/", "note": "תנאי השימוש נבדקו ב-2026-09" }
]
```

`url` הוא עמוד ההתחלה, `include` תחילית הנתיבים שמותר להמשיך אליהם (ברירת המחדל: התיקייה של עמוד ההתחלה),
`maxPages` תקרה לאתר, ו-`note` הערת רישיון שנשמרת עם כל עמוד. הזחלן קורא קודם את `robots.txt` ומכבד אותו,
בקשה לשנייה לאתר (או ההשהיה שהאתר מבקש), עם User-Agent שמכיל כתובת קשר; עמודים נשאלים בבקשות מותנות, ולכן
ריצה חוזרת לא מעמיסה על האתר. תפריטים, כותרות עליונות ותחתונות נזרקים; עמוד קצר מ-400 תווים נחשב תפריט.
כל עמוד נטען כמקור מסוג `website` עם הכתובת, והקטעים מוצגים במענה כציטוט קצר עם קישור. **באחריות המשתמש**
שיש לו זכות להשתמש באתרים שברשימה.

## איך המענה שומר על שלושת הכללים

- **אפס הזיות** (`features/library/ask.ts`): המודל מקבל רק את הקטעים שנשלפו ומתבקש לצטט `[n]`; אחר כך
  `checkGrounding` (ב-`packages/domain/src/library.ts`, נבדק): כל ציטוט מצביע על קטע שנשלף, יש לפחות ציטוט
  אחד, וכל מספר בתשובה מופיע בקטעים המצוטטים; ואז קריאה שנייה נפרדת למודל ששופטת אם כל עובדה קיימת
  בקטעים. כישלון באחת מהן → "לא מצאתי במקורות" עם הקטעים שנשלפו לקריאה. בלי קטע קרוב מספיק המודל לא נקרא
  בכלל.
- **אפס מידע מטופלים**: ל-route אין גישה לטבלאות הקליניקה ואין כלים; שאלה עם מספר זהות (ספרת ביקורת),
  טלפון, אימייל או מספר כרטיס נדחית לפני כל ספק (`findPii`); היסטוריית השיחה חיה בלשונית בלבד.
- **תיעוד**: `library_log_query` רושמת מי, מתי, סטטוס, ואילו מקורות נשלפו (וצוטטו) — בלי תוכן; אין policies
  לשינוי או מחיקה. מסך `/library/activity` מציג אותו לקליניקה.
- **disclaimer**: `LIBRARY_DISCLAIMER_HE` חוזר בכל תשובה של ה-API, בכל סטטוס, ומוצג מתחת לכל תשובה.

## עלות (סדר גודל)

Voyage: כמה סנטים לאלף עמודים (ויש מכסה חינם). Anthropic: כמה סנטים לשאלה (שתי קריאות: תשובה ובדיקה).
המכסה: 60 שאלות למטפל ליום (`LIBRARY_LIMITS.dailyQuota`).

## מה נקרא, ומה עובר דרך Drive

PDF, Word (.docx וגם .doc), RTF, מצגות (pptx), גיליונות (xlsx), EPUB, txt/md, וקובצי Google Docs/Slides/Sheets.
PDF סרוק (בלי שכבת טקסט) ותמונה (jpg/png/tiff/webp) נשלחים ל-Google Cloud Vision באותו חשבון שירות, 5 עמודים
לבקשה, ומספרי העמודים נשמרים (DEPLOY.md, "OCR לסריקות ולתמונות": חיוב + הפעלת ה-API). .doc שהקורא הרגיל לא פותח
נפתח ב-Word המותקן במחשב ונשמר כ-docx זמני. הטקסט נשמר ב-`.cache/library/text/` לפי hash של הקובץ, ולכן OCR רץ
פעם אחת לכל קובץ. כשה-Vision API כבוי — הקבצים האלה נספרים ונרשמים ב-`.cache/library/needs-ocr.json`.

`node scripts/library/ingest.mjs --only=<מילה>` — רק קבצים שהנתיב שלהם מכיל את המילה (לבדיקה של קובץ אחד).

בסוף כל ריצה: `.cache/library/failed.json` (קבצים שנכשלו והסיבה) ו-`needs-ocr.json` (סריקות שחיכו ל-OCR). ריצה
חוזרת מטפלת רק במה שלא נקרא — הטקסט וההטמעות של מה שכן נקרא שמורים במטמון לפי טביעת האצבע של הקובץ, ולכן
קובץ שלא השתנה לא מורד שוב. הריצה מחזיקה מעמד שעות: האסימון של חשבון השירות מתחדש לבד, ובקשה שנפלה ברשת
מנוסה שוב.
